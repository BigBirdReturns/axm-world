# Burn Protocol live evidence projection

## Classification

This transaction carries a verified process-local Burn asset session back into the continuing Rodoh world. It is a presentation projection, not a new cartridge field, engine state, portable-run extension, canonical event, outcome input, or custody transfer.

The base is the qualified holder-controlled external asset receiver. That receiver remains responsible for activation-record binding, index admission, safe path matching, exact file length, SHA-256 verification, and creation of revocable object URLs. This transaction does not repeat or weaken those checks.

## Actors and authority

Arc controls authored law, cartridge identity, and the canonical boundary. The activation records and manifest-derived index control external custody standing. The holder selects local bytes. The external receiver verifies them. The new evidence drawer receives only the resulting read-only session record.

The evidence drawer receives no `ArcWorld`, `ArcInteraction`, challenge, report, resolution, save, export, or state-effect callback. Its available actions are limited to opening, closing, paging verified images, and releasing the process-local session.

## In-process surface handoff

The live player remains mounted beneath the external corpus receiver. Opening the exact Burn cartridge's corpus control updates only the same-origin query surface through History API state. Returning from the receiver removes that query surface without remounting the live player.

This preserves:

```text
live organization state
current cycle
selected representation
pending engine decisions
cartridge identity
process-local verified evidence session
```

It does not create a second save authority. Browser back and forward also update the presentation surface through the same bounded surface subscription.

## Read-only projection

Once exact asset bytes have been verified, the continuing world exposes a **Verified evidence** control. The drawer shows the external evidence standing, file path, classification, byte count, manifest SHA-256, overlay SHA-256, index SHA-256, and authored Arc digest.

Only the object URLs created by the qualified receiver are used. The drawer cannot accept files, revise hashes, promote a fixture, or produce an external reference. A fixture session remains visibly classified as fixture evidence.

## Export and persistence boundary

The qualification exports the run before and after opening the receiver and evidence drawer. After removing the serialization timestamp, the durable run state and extensions must be equal. The exported portable run must contain none of:

```text
asset paths
blob URLs
asset-index format identifiers
external overlay or session records
```

A cold page reload returns to the cartridge bay with the run still resumable, while the evidence control is absent. Re-entering the same live run therefore restores engine state but not external asset bytes.

## Qualification

The dedicated workflow rebuilds the calibrated Arc publication, builds the same decodable content-bound external fixture, runs strict TypeScript and focused custody contracts, builds the ordinary World product, and proves that neither fixture bytes nor fixture paths entered the static build.

Desktop and mobile browser acceptance requires:

```text
exact Burn cartridge opens the receiver without remounting World
engine shell remains mounted beneath the receiver
custody and one raster verify normally
return restores the same live shell
read-only evidence drawer decodes the raster
before and after durable run state is equal
portable run contains no evidence-session material
cold reload preserves run but forgets evidence bytes
no external network request occurs
no horizontal overflow occurs
```

## Evidence ledger

The evidence tier is mechanism qualification; the venue is the stacked live-evidence branch; the target is a production-exact external asset session generated from the private A13C1 handoff; the upside is visual evidence inside a continuing world without engine or custody drift; the downside is that evidence must be reselected after a cold reload; the failure mode is any projection that changes durable run state, enters an export, survives reload, accepts unverified bytes, or allows presentation to satisfy authored law.

The control question is whether verified visual evidence can inform a holder's judgment while remaining unable to alter the world whose history it depicts.
