# Underdrain representation failure analysis

Status: post-v1 system correction after the machine-qualified authored-pilot false positive.

## Executive finding

The second Underdrain miss was not a shortage of art and not a failure of the white-label runtime.

The estate already contained:

```text
6 governed production programs
84 production assets
23 SVG assets
1,531 vector elements
portrait and standing-body dispatch
cartridge emblems and motifs
environment and foreground composition
mobile, reduced-motion, forced-colors, and provenance gates
```

Underdrain bypassed that estate by shipping as an isolated single-file demo whose action surface still drew circles, lines, semicircles, and generic panels.

The playtest system certified it because the authored-experience gate and asset-custody gate were independent:

```text
causal authored structure        PASS
frozen v1 asset inventory        PASS
candidate-specific representation NOT ASKED
conjunctive playable-product gate ABSENT
```

A green structural pilot therefore inherited the dignity of an unrelated historical asset estate without proving that its own people, mechanisms, places, consequences, successor, or record were represented.

That was a project-level acceptance defect. The user correctly refused the result.

## Why the prior playtest missed it

### 1. The one-a.m. gate asked the right causal questions and stopped too early

The permanent gate required:

- inhabited entry;
- role and ordinary stake;
- authored commitment;
- truthful action verb;
- in-play reveal;
- accepted consequence;
- persistent world delta;
- durable record;
- playable successor;
- exact resume.

It did not require a cartridge-owned representation plan. A candidate could therefore satisfy the causal chain using schematic geometry and text panels.

### 2. Asset custody audited a closed historical set

`tests/world/asset-release-custody.test.ts` and `src/assets/rollups/rodoh-v1-programs.json` intentionally described the six accepted v1 programs. That was valid release evidence for v1.

It was not a discovery mechanism for post-v1 candidates.

Underdrain was absent from the rollup, so the inventory could remain exactly green while Underdrain had no entry, no representation plan, and no production assets of its own.

### 3. Browser screenshots were not semantically bound to assets

The browser gate retained screenshots, but it asserted:

- view reachability;
- text and controls;
- accepted receipt IDs;
- state values;
- mobile operability.

It did not assert which cartridge-owned asset identities were visible in each screenshot. A screenshot of a schematic surface counted as evidence because screenshot existence and representation completeness were conflated.

### 4. The standalone verifier bound authoring but not presentation

The standalone was cryptographically bound to:

```text
World commit
Arc commit
authoring.json
single-file HTML
```

It had no independent presentation digest, provenance record, asset registry, surface bindings, or rule that representation must install before boot and resume.

### 5. Release language was not conjunctive

The candidate was called a `machine-qualified authored pilot` when the structural gate passed and the blind-player receipt remained external.

That classification omitted a middle requirement:

```text
structural gate
AND representation gate
```

The correct prior classification was `authored-logic prototype`.

## Attribution

### Player or user error

None.

The user saw a result that looked and behaved like a schematic prototype despite the estate already containing a white-label production system. Rejecting the completion claim was the correct acceptance action.

### Implementation error

1. The Underdrain donor was treated as a special standalone rather than a consumer of the existing representation commodity.
2. Existing white-label portraits, bodies, motifs, environments, accessibility seams, and custody patterns were not routed into the pilot.
3. Browser evidence asserted text and state but not governed visual identities.
4. The standalone verifier had no presentation digest.
5. The previous pass report did not compare the candidate against the estate's production-dignity floor.

### Project-level debt

1. No candidate-discovery gate connected post-v1 authored pilots to asset custody.
2. No representation schema connected authoring, assets, runtime surfaces, devices, and accessibility.
3. No conjunctive product evaluator prevented structural evidence from standing in for presentation evidence.
4. No required surface list made cold entry, commitment, action, consequence, successor, and record equally responsible for representation.
5. No explicit classification existed between authored logic and machine-qualified product.

## Permanent correction

### Candidate-bound representation law

`rodoh-representation-plan/1` now binds:

- candidate repository, authored identity, and experience;
- unique cartridge namespace;
- original-asset provenance;
- identity emblem;
- required people and portrait/body equivalents;
- each mechanism's idle, active, and complete states;
- every persistent state the player must understand;
- cold entry, authored commitment, first action, accepted consequence, playable successor, and durable record;
- desktop and mobile coverage;
- nonvisual equivalents;
- action renderer class and neutral-fallback refusal.

The evaluator refuses:

- primitive-only action rendering;
- first-party neutral fallback;
- placeholders, generic art, debug geometry, wireframes, and prototype assets;
- missing cast, mechanism, state, or surface bindings;
- desktop-only or mobile-only representation;
- missing accessible equivalents;
- unnamespaced or missing source assets;
- absent provenance.

### Candidate discovery

The asset estate no longer assumes that membership in the frozen v1 rollup is the universe of first-party products.

The new discovery test walks authored demo candidates. Every `authored-pilot-candidate` or stronger classification must have a sibling representation plan that passes the shared evaluator and whose source and provenance files exist under candidate custody.

A future first-party pilot cannot be omitted from asset acceptance merely because no one remembered to add it to a historical rollup.

### Conjunctive classification

`rodoh-playable-product-evaluation/1` now applies this ladder:

```text
structural FAIL or representation FAIL
  -> rejected

structural PASS and representation PASS
blind-player receipt absent
  -> machine-qualified-authored-pilot

structural PASS and representation PASS
blind-player receipt PASS on same identity
  -> accepted-playable-authored-episode
```

### Representation before boot

The Underdrain builder now separates runtime definitions from application boot:

```text
embed exact authoring
embed exact representation plan
install local persistence
install cartridge art registry
load action and episode definitions
install represented renderer and evidence decorator
boot cold entry / resume / automated matrix
```

A saved action cannot render one schematic frame before the represented renderer takes control.

### Exact static custody

The verifier now requires:

- exact representation SHA-256;
- byte-identical embedded and companion plans;
- at least forty candidate-owned assets for this production pack;
- six people;
- five mechanism objective bindings;
- seven persistent-state marks;
- all six required player surfaces;
- desktop/mobile parity and accessible equivalents;
- original provenance and existing source files;
- represented renderer installed before boot;
- no primitive-only or neutral-fallback declaration;
- executable, offline, deterministic single-file output.

### Browser evidence

Desktop and mobile cold walks now assert and retain screenshots for:

```text
represented cold entry
represented safe service mechanism
represented authored commitment
represented Pump Seven operation
represented accepted consequence
represented Root Gate successor
represented durable record
```

The browser also asserts asset identities through `data-presentation-asset`, canvas `data-representation-assets`, and the final `rodoh-representation-runtime-evidence/1` record.

Screenshot existence alone no longer proves visual completion.

## Why the system should now get faster

The expensive part was discovering the acceptance plane. That discovery is now encoded once.

The next cartridge does not begin by inventing a new visual test philosophy. It begins with a generated representation-plan skeleton and receives immediate failures for missing:

- identity;
- cast;
- mechanisms;
- persistent states;
- six journey surfaces;
- mobile coverage;
- accessibility;
- provenance;
- runtime mounting.

The reusable sequence is now:

```text
1. Author Arc identity, objectives, states, and successor.
2. Generate required representation roles from those authorities.
3. Fill the cartridge-owned pack through the shared white-label seams.
4. Run structural and representation evaluators before browser work.
5. Assemble exact standalone or native receiver.
6. Run desktop/mobile surface walks.
7. Retain candidate-bound screenshots and evidence.
8. Seek the independent blind-player receipt only after machine gates pass.
```

This should make later pilots faster in two ways:

1. **Earlier refusal.** Missing production surfaces fail before long browser, Windows, Unity, or device trains.
2. **Commodity reuse.** Every new cartridge reuses the same schemas, dispatch, responsive rules, accessibility law, verifier, screenshots, and classification ladder. Only its authored identity and assets remain cartridge-specific.

## Closure condition

This second correction is complete only when one exact Underdrain head proves:

1. structural authored experience;
2. candidate-bound representation plan;
3. original provenance;
4. cartridge assets mounted before boot;
5. represented cold, commitment, action, consequence, successor, and record surfaces;
6. desktop/mobile parity;
7. static exact-byte verification;
8. discovery by global asset custody;
9. full regression, browser, local-estate, and artifact gates;
10. honest `machine-qualified-authored-pilot` language until the independent receipt exists.

The independent zero-assistance one-a.m. receipt remains deliberately external. Unity import, native Windows-player, Quest, headset, tracking, guardian, and physical-session evidence remain separate acceptance planes.
