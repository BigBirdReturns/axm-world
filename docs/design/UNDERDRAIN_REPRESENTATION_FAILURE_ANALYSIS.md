# Underdrain representation failure analysis

Status: active system correction after two successive representation false positives.

## Executive finding

The user screenshot was correct evidence that the previous correction had not closed the product boundary.

The build had two separate defects:

```text
objective and touch UI covered the rendered world
48 representation roles were reported as 48 cartridge assets
```

The first defect made play visually obstructed. The second defect made the evidence misleading.

The actual Underdrain inventory at the time of refusal was:

```text
declared representation roles   48
independent production roles      1
prototype roles                  47
production sources                1
```

The one production source was the 960 x 540 Pump Seven WebP. The other roles were generated by one procedural prototype renderer. Giving that renderer 47 different semantic IDs did not create 47 production assets.

The authored episode, deterministic action law, exact Arc acceptance, persistence, and continuation remained valid. The representation and release classification did not.

## Failure history

### First miss: authored structure without candidate representation

The initial Underdrain receiver passed deterministic and authored-structure gates while rendering schematic geometry.

```text
causal authored structure        PASS
frozen v1 asset inventory        PASS
candidate-specific representation NOT ASKED
```

That allowed a new candidate to inherit the dignity of unrelated historical asset packs.

### Second miss: role-plan completeness treated as production completeness

The first correction added a candidate-bound representation plan containing:

- six people;
- five mechanisms with idle, active, and completed states;
- environments;
- route marks;
- persistent-state marks;
- pressure actors;
- evidence and record roles;
- all six player surfaces.

The plan was useful as an obligation map. The implementation then made a category error: it counted every role ID as a completed asset even though nearly all IDs pointed to `assets/underdrain-art.js`, one procedural prototype renderer.

The visible badge, workflow receipts, and reports repeated the inflated phrase **48 cartridge assets**.

A semantic role is not a source file. A source file is not automatically production art. A runtime identity is not proof of visual dignity.

### Third miss: containment tested the wrong container

The mobile geometry gate required touch targets to remain inside `.stage`. That sounded safe and certified the opposite of what the player needed.

Because the objective ribbon and controls were descendants of the stage, the test could prove:

- controls inside the stage;
- minimum target size;
- no button overlap;
- label containment;

while the controls still covered much of the actual game image.

The gate optimized containment inside the wrong coordinate space. It never measured intersection with the canvas or the visible action region.

## Attribution

### Player or user error

None.

The user saw that the action scene was obstructed and that the alleged asset quality did not match the estate's production standard. Rejecting the completion claim was the correct acceptance action.

### Implementation error

1. The special standalone bypassed the existing white-label production train.
2. Candidate role IDs were conflated with independently authored production sources.
3. One procedural renderer was allowed to satisfy dozens of role slots.
4. Screenshot existence was treated as visual evidence without assessing obstruction or production quality.
5. Control geometry was measured against the stage rather than against the canvas as a protected region.
6. Release language promoted a role-plan pass into machine-qualified status.
7. Human screenshot review happened after the classification claim instead of before it.

### Project-level debt

1. No separate production-coverage receipt existed.
2. Representation metrics had only an asset count, not declared/production/prototype partitions.
3. The playable-product evaluator could not distinguish role completeness from production completeness.
4. The command UI and rendered world shared one layout container.
5. Mobile acceptance had no protected-world intersection test.
6. Global asset custody discovered candidate plans but not honest source coverage.
7. Retained screenshots were artifacts, not mandatory reviewed inputs to classification.

## Permanent correction

### Role plan and production coverage are now separate

`rodoh-representation-plan/1` describes what must exist:

- identity;
- cast;
- environments;
- mechanism states;
- pressure actors;
- routes;
- persistent state;
- evidence;
- durable record;
- player-surface bindings;
- accessibility equivalents.

`rodoh-representation-production/1` describes what actually has exact production custody:

- covered role IDs;
- exact source paths;
- media type;
- SHA-256;
- dimensions where relevant;
- coverage status: `prototype`, `mixed`, or `complete`.

The shared evaluator now reports:

```text
declaredRoles
productionRoles
prototypeRoles
productionSources
```

It fails release representation when:

- production coverage is absent;
- coverage is prototype or mixed;
- a production role has no exact source;
- a source binds undeclared roles;
- a source has no digest or path;
- complete status leaves any prototype role.

Current Underdrain therefore fails the release representation gate honestly:

```text
declaredRoles     48
productionRoles    1
prototypeRoles    47
status             mixed
```

### The canvas is now protected space

The layout is structurally separated:

```text
stage-shell
├── stage
│   ├── canvas
│   ├── HUD
│   └── recovery surface
└── command-deck
    ├── objective
    └── touch controls
```

No objective or touch-control node is a descendant of `.stage`.

Reference layouts:

- desktop: objective deck below the canvas; touch hidden;
- 390 x 844 portrait: command deck below the canvas;
- 844 x 390 landscape: command deck in a dedicated right rail.

The new geometry gate calculates actual rectangle intersections and requires zero overlap between:

- canvas and command deck;
- canvas and objective ribbon;
- canvas and touch cluster;
- canvas and each individual control;
- stage and command deck.

It also requires 44 x 44 targets, contained labels, no button overlap, and minimum unobstructed canvas dimensions.

### Exact production source custody

The Pump Seven production scene is decoded from five tracked base64 chunks. The builder and verifier require exact bytes:

```text
underdrain:scene-pump-seven
image/webp
960 x 540
sha256:c5810b7362b511a8789e26300517ab0156b2593f99c9b45227765f465ef871ca
```

The runtime records its exact production role and digest. Prototype player, mechanism, enemy, and UI annotations remain classified as prototype work.

### Candidate discovery now includes coverage

Global asset custody discovers first-party authored candidates and requires:

- `presentation.json`;
- `production.json`;
- provenance;
- source confinement;
- exact production source digests;
- shared evaluator results.

A mixed candidate can remain in the repository as a rework, but it cannot pass the release representation gate.

### Faster refusal

The fast scaffold derives required people, objectives, states, and six surfaces from Arc authoring before browser work. It now also reports real production coverage.

The expected early receipt for current Underdrain is:

```text

role plan          48 declared roles
production         1 role / 1 source
prototype          47 roles
release state      blocked
```

This is faster because the expensive browser, Windows, Unity, and device trains are no longer needed to discover that art is missing.
