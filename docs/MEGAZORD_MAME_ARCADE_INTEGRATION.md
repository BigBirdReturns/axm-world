# Megazord integration through the existing MAME-derived arcade floor

## Identity correction

The cabinet integration must preserve three separate identities:

```text
PROGRAM OF RECORD — Strategy
  an existing defense-acquisition strategy game
  AXM-WORLD Cartridge No. 03

RODOH ProgramOfRecord registry
  a computed-cartridge-identity admission registry
  current controlled entries include Program 001, 004, and 005

The First Charter
  the cartridge admitted as Program 001
  not the game titled PROGRAM OF RECORD
```

The branch-local twelve-chapter `First Charter Program of Record` was not an estate authority and has been removed. The five Classic Trials remain unassigned executable prototypes until an actual cartridge owner and source-grounded story brief assign them.

## Existing cabinet law

MotionDeck Cabinet Floor and QuestStage already own the household machine boundary. Infinite Fabric, Demo Forge, Rodoh, and the commodity-model harness must not create a second cabinet, launcher, title database, adapter detector, profile stack, trust authority, session authority, or household frontend.

MAME contributes two different things:

1. a real emulation runtime and software supplier for legally held arcade content; and
2. the machine-driver and software-list architecture used by the holder-owned cabinet.

```text
MAME machine driver     -> runtime or game-machine topology
MAME software list      -> admitted title and cartridge catalog
ROM evidence set        -> immutable source, build, asset, and receipt bundle
DIP switches            -> difficulty, age, control, device, and policy profile
input ports             -> semantic actions and physical control bindings
lamps / outputs         -> score, state, haptics, gates, and receipts
save state              -> deterministic attempt checkpoint
NVRAM                   -> retained progress and cabinet history
watchdog                -> stuck process, stale authority, and provider neutralization
attract mode            -> title preview, Demo Forge, and unattended showcase
plugin sidecar          -> MAME Lua, provider adapters, observers, and bridges
replaceable frontend    -> MotionDeck Home, Rodoh, MAME, browser, or future shell
```

## Generated-game lane

Generated games remain useful, but the factory consumes an actual source-grounded brief rather than an invented Program of Record or cartridge canon.

```text
select an existing cartridge or approved new-game brief
→ bind its actual world, mechanics, controls, and consequence authority
→ select an admitted Canvas, Three.js, or other machine profile
→ route planning, implementation, assets, observation, and repair to commodity seats
→ build through host-owned commands
→ verify ordinary start, win, loss, restart, save, outputs, and provider-off play
→ package as a candidate software item
→ assimilate through MotionDeck
→ assign cartridge canon only through a separate owner acceptance
```

The Classic Trials may exercise this lane as unassigned prototypes. They are not First Charter chapters, ProgramOfRecord entries, or the game titled PROGRAM OF RECORD until an authoritative source transaction says otherwise.

## Production order

```text
1. Recover and fingerprint the exact PROGRAM OF RECORD standalone.
2. Assimilate it as one MotionDeck software item without changing its engine.
3. Bind its existing modes, seats, doctrines, table presets, inputs, outputs,
   save state, NVRAM, and watchdog behavior.
4. Launch SOLO VS CPU and PASS & PLAY from the ordinary household catalog.
5. Return to the same cabinet shell with retained game state.
6. Reclassify the five Classic Trials as unassigned candidate software items.
7. Inventory the actual First Charter, Waking Tower, Ilyon, Lamp District,
   and Relief Circuit source before assigning any generated game to their canon.
8. Run one source-grounded generated-game brief through the same cabinet path.
9. Prove that Program of Record, MAME, Steam, Rodoh, and generated candidates
   coexist without a second cabinet authority.
```

## Refusal boundary

A generated or adapted game is refused when it invents a title identity, registry standing, cartridge canon, story consequence, or program number. It is also refused when it requires another launcher, title database, profile system, trust system, session authority, frontend, or process supervisor.

## Control question

Can the same MotionDeck cabinet preserve the exact identity and live mechanics of PROGRAM OF RECORD — Strategy, while also admitting MAME titles, Rodoh cartridges, Steam games, prototype arcade games, and generated candidates without confusing title identity, registry standing, cartridge canon, or household authority?
